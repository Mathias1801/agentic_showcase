Portfolio project — multi-agent systems

An analytics agent that's designed to be told "no."

A four-agent pipeline that answers natural-language business questions against a real dataset — but the interesting part isn't the answers, it's the four independent, mostly-deterministic checks that stand between a generated narrative and the stakeholder seeing it. Every example below is a real run against real OpenAI + Claude Haiku 4.5 API calls, not a mockup.

4 specialized agents 4 independent guardrail layers cross-provider critic (OpenAI generates, Claude judges) 75 tests passing 7 real bugs found & fixed via live runs

Why not just ask a chatbot?

A single LLM call can already produce a fluent, confident-sounding answer to "why did margin drop this quarter." The problem it can't solve on its own is telling you when that confidence is unearned. This project exists to fix that, structurally — not by prompting harder, but by taking verification out of the model's hands wherever possible.

This pipeline
Numbers in the answerComputed once, outside any LLM, straight from the retrieved rows (pandas/numpy). Every number the narrative contains is checked against that set — twice, by two independent components.
Root-cause claimsA rule-based causal-language scan flags any "why / caused by / driven by" claim for human sign-off — independent of what any model thinks of its own answer.
"Let me double-check that"Reviewed by a model from a different vendor entirely — Claude Haiku 4.5 judges what OpenAI gpt-5.4-nano wrote. Different pretraining data, different alignment process, uncorrelated blind spots.
Thin evidenceA deterministic, row-count-based confidence threshold blocks trend/comparison claims that don't have the data to back them.
Failure modeFails closed — unparseable judge output, failed grounding, or low confidence all withhold the answer instead of defaulting to showing it.
DebuggabilityEvery rejection carries a specific, inspectable reason from a specific guardrail — see the live examples below.

Pipeline

Straight-line, hand-built — no orchestration framework. One question in, one Critic-approved (or rejected, or held) report out.

01 · RETRIEVAL

NL → SQL

Question → validated, read-only, schema-bounded SQL → rows. Row cap, token budget, one self-correction retry.

→
02 · ANALYSIS

Facts → narrative

Stats computed in pandas/numpy, never by the LLM. The model only narrates about facts it's given, and every number it writes is checked back against them.

→
03 · CRITIC

Four-layer QA

Independent grounding re-check, confidence threshold, human-in-the-loop causal scan, and a cross-provider LLM judge.

→
04 · REPORT

No LLM call

Pure formatting. A rejected or low-confidence result structurally cannot be presented as a clean answer.

The four checks, in agents/critic_agent.py

1. Independent grounding re-check

Re-verifies every number in the narrative against the computed facts from scratch — doesn't trust the Analysis agent's own self-report, in case that check had a bug.

2. Data-sufficiency confidence

Row-count-based threshold for trend/ranking claims specifically. A one-row "total revenue" answer isn't penalized — a two-point "trend" is.

3. Human-in-the-loop scan

Rule-based, not model-based: any causal language ("caused by," "driven by," "the reason...") gets flagged for a person to confirm, regardless of whether it otherwise passes.

4. Cross-provider LLM judge

Claude Haiku 4.5 — a different vendor from the OpenAI model that generated the narrative — gives a structured verdict: does it answer the question, and is every claim actually supported.

Proven against real API calls, not just fixtures

75 hand-written tests use fake LLM clients and passed the whole way through development. None of the seven bugs below were caught by them — every one only surfaced by actually running the pipeline against real OpenAI and Claude Haiku 4.5 calls. That gap is the reason this showcase exists as a live run rather than a scripted demo.

Grounding rejected the question's own timeframe

A narrative answering "...in 2025" naturally restates the year — but the grounding check only allowed numbers from computed facts, never the question, so almost every time-scoped answer failed to ground. Fixed in both the Analysis agent's check and the Critic's independent re-check.

Fence-stripping bug corrupted every JSON-fenced response

text[3:] was hardcoded for a 3-letter fence tag ("sql") and silently mis-sliced 4-letter ones ("json"), leaving a stray character glued onto valid JSON and breaking every Critic verdict.

Critic only read the first content block

response.content[0].text isn't guaranteed to be the whole answer — real Claude Haiku responses were silently discarded as empty strings.

Confidence guardrail penalized every single-row answer

"Total revenue in 2024" legitimately returns one row — that's a complete answer, not insufficient data. Fixed by distinguishing single_value results from trend/ranking claims that actually need multiple data points.

Schema didn't expose exact stored values

The model knew a category column existed but guessed 'Home and Garden' instead of the real 'Home & Garden' — valid SQL, zero rows, no error.

Schema never explained how tables join

The model wrote a column directly on the wrong table by analogy with a similarly-named column elsewhere. Fixed by dynamically inferring and documenting join keys in the schema text.

Small-model JSON quoting quirk

Claude Haiku occasionally escapes an apostrophe as \' — invalid JSON — throwing away an otherwise-correct verdict. Hardened to repair that one known-safe pattern; still fails closed on any other malformation.
